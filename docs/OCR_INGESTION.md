# 本地规范识别与检索

网站的“本地 PDF 识别”只在浏览器内读取用户选择的文件。PDF.js 先读取文字层；缺少可用中文文字层时，Tesseract.js 使用 `chi_sim` 对渲染后的页面进行 OCR。单次最多 12 页，按 PDF 实际页码保存到当前浏览器 IndexedDB。原 PDF 不上传，首次 OCR 需要下载模型。相同文件按 SHA-256 区分，重复导入同一页会更新该页。

“条文检索”会显示本机页级命中，但 OCR 结果不进入人工核对过的 `ruleCorpus`，也不自动运行函数审计。每条本机结果都保持 `REVIEW_REQUIRED`。PDF 中的公式、上下标、表格、页码与修订标记可能被识别错误，必须对照原页校核。

离线批量识别使用相同的文字层优先原则，并将结果写入本地 JSONL；不会修改源 PDF：

```powershell
node scripts/ocr-codes.mjs --input 'E:\规范库' --output 'E:\规范库\.ocr-index' --max-pages 12
```

再次执行会跳过已处理页并继续下一批。`--force-ocr` 可对文字层有缺陷但通过初步质量检查的页面重新识别；对已完成页需使用新的输出目录。可用 `--pdftoppm <可执行文件路径>` 指定 Poppler 渲染器。没有经过人工核对的 JSONL 不应提交公开仓库或作为现行设计结论。

这种索引是本地、页级关键词检索，还不是跨设备共享的向量 RAG。后续新增规范时仍需人工确认标准编号、版次、来源、条文边界和影响的计算函数。
